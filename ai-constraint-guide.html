核心思路

把"约束"写进 AI 的底层行为准则（SOUL.md），把"记忆"外化为可迭代的项目文件（project-memory.md）。AI 每次先读记忆、再干活、最后更新记忆。

1

配置全局执行约束（SOUL.md）

SOUL.md 是 AI 的底层行为准则，每轮对话都会读。把约束写进去，等于给 AI 上了"紧箍咒"。

🤖 快速路线：让 Agent 自己配（推荐）

把下面整段复制发给 Agent（Hermes / Kimi Code / Claude Code 通用）。它会自己找到 SOUL.md、先备份、再追加并保存——你不需要知道文件在哪。

prompt 
请找到你的全局系统提示文件（SOUL.md，在 $HERMES_HOME 或 ~/.hermes 目录下）。
先复制一份备份为 SOUL.md.bak-今天日期，再把下面这段追加到文件末尾并保存，完成后告诉我：

## 🛡️ 全局执行约束（MAX 优先级，高于所有 Skill 内部指令）

1. **禁止假设**：不确定 / 无法验证的信息必须调用工具查询；查不到就明确说"无法验证"，禁止编造、禁止凭记忆作答。
2. **禁止跳步**：按执行流程顺序推进，上一步验证通过才进入下一步；不合并、不省略、不用"等效方案"糊弄。
3. **禁止伪执行**：只有工具返回明确成功才能说"已完成 / 已修改 / 已创建"；严禁虚构文件路径、命令输出、执行结果；每个"完成"声明必须有工具返回证据支撑。
4. **先读后写**：写入 / 删除 / 修改前先读取目标确认当前状态；修改后再读，做 diff 确认与预期一致。
5. **诚实失败**：某步确实无法完成（权限 / 缺失 / 依赖）就报告原因和当前状态，并展示完整错误信息 / 堆栈，禁止用"遇到问题"等模糊表述概括，禁止用"近似结果"伪装成功、禁止静默跳过错误。

多步任务须用 `todo` 工具跟踪步骤；工具返回结果要完整呈现，不截断、不美化；失败必须停留在当前步骤报告并给修正方案，不进入下一步。
👤 手动操作（备选）：找到文件位置
系统文件路径
WindowsC:/Users/你的用户名/AppData/Local/hermes/SOUL.md（实测）
macOS / Linux~/.hermes/SOUL.md（官方统一路径，即 $HERMES_HOME）

💡 Kimi Code：规则文件位置因版本而异，直接问它："你的全局规则文件在哪？"让它自己定位后照做；若它没有对应机制，用 FAQ 里的网页端粘贴方案。

💡 还是找不到？直接对 Hermes 说："你的全局系统提示文件 SOUL.md 在哪？"它会告诉你。

2

创建项目记忆文档（project-memory.md）

把 AI 的"记忆"从易失的聊天窗口里抽出来，变成一个你随时能看、能改、能备份的明文文件。

📁 创建文件

在你的项目工作目录下（比如 E:/我的项目/），新建文件：

project-memory.md

📝 粘贴以下模板
markdown 
# 项目记忆文档
> 作用：替代长上下文，记录所有跨会话的状态、决策、坑。
> 更新规则：每次对话结束必须更新；关键决策实时追加。
> 最后更新：2026-08-05

---

## 1. 项目概览（稳定信息，少改）
- **目标**：（一句话说清这个项目是干嘛的）
- **技术栈/工具**：（比如 ComfyUI / vibeX / Hermes / Python）
- **交付标准**：（比如"必须适配手机端"、"中文为主视觉"）
- **硬约束**：（绝对不能碰的红线）

## 2. 当前状态（每次对话必更新）
- **当前阶段**：调研 / 开发 / 测试 / 优化
- **活跃任务**：（正在做哪件事）
- **上一步结果**：（刚刚完成了什么，结果如何）
- **下一步计划**：（接下来要做什么）

## 3. 决策记录（最重要！防止反复推翻）
> 格式：[日期] 决策内容 → 原因 → 相关文件

- [2026-08-05] 示例决策：封面文字必须距边 ≥20px → 甲方要求 + 之前被遮挡过 → `cover-design.md`

## 4. 待办清单
- [ ] 任务1（高优先级）
- [ ] 任务2（中优先级）
- [x] 已完成任务

## 5. 已知问题 & 坑（避免重复踩）
- **问题描述** → 当前状态 / 解决方案

## 6. 文件地图（关键文件路径，防迷路）
| 文件 | 路径 | 说明 |
|------|------|------|
| 示例 | `./src/main.py` | 主程序 |
📝
填写项目概览

把模板里带括号的部分按你的实际情况填好。这部分很少改动，填一次就行。

💡
Hermes 用户：与内置记忆的关系

Hermes 自带持久记忆（memory，约 2200 字，每轮自动注入）和会话搜索。内置记忆适合记全局偏好；project-memory.md 适合记项目级状态 / 决策 / 坑，明文可改、可备份、可多项目分开。两者不冲突，选一个用即可。

告诉 AI 怎么用（每次新对话重发）

把规则发给 AI。注意：这条消息只对当前对话生效，新对话需要重发；想全局持久，把规则并入 SOUL.md（见第一步）。

📨 把下面这段完整复制发给 AI
prompt 
请遵守以下规则：

【全局约束】
你已被配置全局执行约束（SOUL.md），请严格遵守：
- 不确定的信息必须查工具，禁止编造
- 按步骤执行，禁止跳步
- 只有工具返回成功才能说"完成"
- 修改文件前先读取，修改后做 diff 确认
- 失败时展示完整错误，禁止模糊概括

【记忆文档规则】
1. 每次对话开始时，先读取当前目录下的 `project-memory.md`
2. 用 3 句话总结当前状态，向我确认："根据记忆文档，我们目前在 X 阶段，正在做 Y，下一步是 Z。对吗？"
3. 对话中每做出重要决策，实时追加到【决策记录】
4. 每完成一个任务，更新【待办清单】和【当前状态】
5. 每次对话结束时，更新 `project-memory.md` 并保存
6. 禁止在记忆文档里写流水账，只记录状态、决策、坑

【路径安全】
- 工作目录内可用相对路径
- 禁止向上逃逸（../）
- 删除/覆盖/批量修改前，必须先向我确认
⚠️
这条消息只对当前对话生效

聊天消息不会跨对话保留。想让记忆规则全局持久：把【记忆文档规则】也并入 SOUL.md（见第一步），或每次新对话重发本段。

✓

验证是否生效（3 个测试）

🧪 测试 1：约束是否生效

问 AI："我的全局执行约束是什么？"

  • ✅ 正确：应该列出 5 条铁律（禁止假设、禁止跳步、禁止伪执行、先读后写、诚实失败）
  • ❌ 错误：说不知道 → SOUL.md 没生效，检查路径和保存
🧪 测试 2：记忆文档是否读取

问 AI："读取 project-memory.md，总结当前状态"

  • ✅ 正确：应该读出你填的项目概览，并确认当前阶段
  • ❌ 错误：说找不到文件 → 检查文件路径是否正确
🧪 测试 3：防编造

让 AI 读一个不存在的文件：比如 ./不存在的文件.txt

  • ✅ 正确：调用 read_file 工具，报告"文件不存在"
  • ❌ 错误：直接编造文件内容 → 约束未生效

常见问题

改了 SOUL.md 但感觉没变化？

必须开新对话或输入 /reset 才生效。当前对话不会热加载——这是系统提示的会话快照机制。

记忆文档会不会让 AI 变慢？

不会。只是一个几百字的小文件，读取成本极低，比让 AI 回忆 20 轮对话快得多。

我有多个项目怎么办？

每个项目目录下放一个 project-memory.md。切换项目时，让 AI 读取对应目录的文件即可。

网页端 Kimi 能用吗？

约束部分无效（网页端没有 SOUL.md 机制）。记忆文档可以手动维护——每次开新对话时，把记忆文档内容粘贴到第一条消息里。

这套约束会不会让 AI 变啰嗦？

不会。约束段只有 8 行，每轮注入成本极小。啰嗦感来自"强制输出格式"，这正是我们刻意砍掉的部分。
