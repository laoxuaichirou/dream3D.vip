"每天 2,000 积分"是误读

打开 WorkBuddy 的「套餐与积分」页，看到的是 2,000 / 2,000。但拆开看是三个数加出来的，而且刷新周期是按月：

套餐基础积分
500
平台奖励积分
1,500
购买积分
0

三条修正，逐条对：

① 不是"每天"，是每月 2,000，页面写明「下次刷新时间 2026/12/01 00:00」。

② 其中 1,500 是「首月赠送个人标准版基础积分权益」，11/6 已领取，限时加赠 11/30 截止 —— 属于一次性，不是长期额度。

③ 这是 WorkBuddy 的额度，不是 CodeBuddy 的。页面悬停写明：「当前仅用于 WorkBuddy。加入 BuddyOne 后，关联产品可共享 WorkBuddy 积分」→ 默认不互通，要先加入 BuddyOne 并关联。

那 CodeBuddy CLI 花的什么钱？

实测结果是 total_cost_usd: 0、permission_denials: []，说明它没被拦、也没报扣费。这与"体验版不支持 CLI"的官方定价表矛盾——表格写的是体验版「—」、标准版起「✓」，但实际当前账号跑通了。

最可能的解释是 Hy4/Hy3 限免期（至 11/15）走了 0.00x 倍率。但 CLI 自报 $0 ≠ 平台没扣积分，还得去客户端看余额有没有动，这一步不能省。

批量任务 ≠ ark key

凡是"写个循环跑 N 条"的事，一律不许碰 Coding Plan 的 key。正确通道只有三条：

任务正确通道
批量文本处理、分类、归类DeepSeek 官方（夜间半价）或 Hermes 对话内跑
批量反推盲跑codex exec（Codex 是官方支持客户端，合规）
大批量生图 / 视频Agnes（$0）
语音克隆本地 IndexTTS

前缀解决不了并发写

给执行器加 hermes_ / codex_ / zcode_ / codebuddy_ 前缀，只能回答"这是谁干的"，不能防止两个进程同时写同一个文件。真正的护栏是这五条：

run 独占目录

每个任务一个 任务总线/T-20261106-01/，执行器只写自己的目录。

claim 租约

用 CreateNew 独占创建 claim 文件，拿到才开工；抢不到直接退出，不重试。

manifest

记 UTC 时间、CLI 版本、模型名、退出码、是否超时、产物 SHA256。

单写者台账

_执行者.md 每 run 一份；CSV 汇总只由 Hermes 一个人写。

免费额度要设准入，别把窗口耗在排队上

  • 准入公式：预计时长 ≤（窗口结束 − 现在 − 提前停止接单时间）× 可用并发 × 0.7
  • 硬超时 + 杀整进程树（Windows 下 taskkill /PID 用单斜杠，MSYS 里 //PID 无效）
  • 熔断：失败率 > 30% 或 p95 超阈值 → 停该执行器，任务转 Codex
  • 截止前停单，不赌"再跑一个"

ZCode 现在卡在哪

本机跑的是正式安装版 G:\Zcode\ZCode.exe（多进程 Electron），登录态在 ~/.zcode/。CLI 入口是有的：

$ node G:/Zcode/resources/glm/zcode.cjs --help
zcode 0.17.1
  -p, --prompt <text>     单次提问，不进 TUI
  --mode build|edit|plan|yolo|guarded
  --cwd <path>   --surface <terminal|desktop>
  doctor · login [zai|bigmodel] · app-server · skills · plugins

但裸跑 prompt 会失败：

$ node zcode.cjs -p "只回复两个字：正常" --mode plan
SdkError: Version negotiation failed:
  the transport was closed during the server/discover probe
// 日志真因：MCP server connection failed / Session runtime closed

它默认挂 6–7 个 MCP（documents / pdf / presentations / spreadsheets / zcode-site / node_repl + image_search）。这些 server 需要 App 的会话运行时——由 App 自己拉起时 6/7 连上、63 个工具；脱离 App 就全挂。

结论修正：不是"没有 CLI"，而是"CLI 存在，但被设计成由 App 拉起"。

要做自动化得走 app-server 协议（stdio），或等官方给独立 CLI 安装方式；现阶段只能当人肉工具用 TUI。另发现 plugin:image-search 报 "coding plan is required" —— 部分插件要付费套餐才给用。

再往下挖：app-server 协议已打通 80%

tui 子命令这版没打包（Cannot find package '@zcode/tui'），但 app-server 能起来，吃的是自定义行分隔 JSON（不是标准 JSON-RPC，带 jsonrpc 字段直接被拒）。实测已经达成：

// 客户端必须应答服务端的请求，否则卡在 starting
[REQ]  session/requestRuntimePreferences  → {"nativeSearchEnhancementsEnabled": true}
[STATE] ready
[SID]  sess_c5319eb4-...
[process/mcpTelemetry] configuredCount 6, connectedCount 6, failedCount 0
[SEND] session/send {"sessionId":"sess_...","content":"只回复两个字：正常"}
[turn.started] → [turn-failed]   // "model": {"available": []}

会话能建、MCP 6/6 全连、prompt 能投递。卡在最后一步：模型注册表为空。

// 指定模型后报的错
Provider Registry 中不存在 Model: bigmodel/glm-5.3-flash

根因：注册表由 App 启动时注入（OAuth 凭据换来的模型清单），CLI 侧没走这条注入。三步待试：① providerId 换成 coding-plan:builtin:bigmodel-coding-plan；② 补 requestRuntimePreferences 的白名单键；③ 抓 App 注入的参数。

不要为了绕过去让脚本直调 api.z.ai —— 那是订阅额度外调，属封号风险。协议没打通之前，ZCode 只算"人肉夜间工具"，不进自动调度。

能不能像火山 / DeepSeek 那样接进 Hermes？不能。

Copilot 没有官方 OpenAI / Anthropic 兼容端点，只有 GitHub 自家客户端的授权通道。拿它的 token 去接第三方工具或自建代理 = 违反 GitHub 条款，和"火山订阅 key 拿去 curl"是同一条红线。所以别切主 provider，也别让 CC Switch 把它当 Codex/Hermes 的上游。

合规用法只有一种：GitHub 官方 Copilot CLI。本机已装好并跑通版本查询：

$ npm i -g @github/copilot
// 失败：AppData\Local\copilot 是 junction → 指向 Codex 的 MSIX 缓存（跨卷）→ EXDEV
$ winget install GitHub.Copilot
✓ MSI v1.0.106 → %LOCALAPPDATA%\GitHubCopilotCLI\copilot.exe
$ copilot --version
GitHub Copilot CLI 1.0.106.

绕坑的关键是 COPILOT_PKG_CACHE_HOME（它要往那个 junction 里解包，跨卷必然失败），已写入你的用户环境变量指向 G:\AIcoding\copilot-pkg。

登录只能走 device flow：经典 PAT（ghp_）被明确拒绝，提示 Classic Personal Access Tokens are not supported by Copilot；fine-grained PAT 需要勾 "Copilot Requests" 权限。

给它分配什么活（杂活专用）

接不接
批量文件改名 / 归档 / 去重清单需要长上下文推理的大活
代码 lint、格式化、死链检查批量 LLM 生成（反推、盲跑、批量改写）

路由规则：单文件 / 短任务 / 有明确验收标准 / 纯机械 → Copilot CLI；要长上下文、跨文件推理、烧大 token → Hermes 或 Codex。

顺便：Codex 的"已过期"不是订阅失效

界面显示 Codex「已过期」，实际是 ChatGPT 周额度用完，5 天后自动恢复。订阅没断，别为这个去重订。

影响的只是这 5 天的路由：耗 token 的重活暂时只能给 CodeBuddy CLI（限免期）、火山 CP（等 key）、或 DeepSeek 夜间（花钱）。

安全提醒：~/.cc-switch/copilot_auth.json 里存着你的 GitHub token（40 位）。这个文件不要外发、不要打进任何分享包。

07

五条会封号或白花钱的红线

ark key 只许编程工具自己发请求。Hermes、Codex、Claude Code、Cursor、Cline、OpenCode 是官方清单内的；curl、python requests、Postman、脚本循环一律判滥用。
批量推理不吃订阅额度。方舟 Batch Inference 是标准服务的 5 折后付费，另一条计费链路，别指望它省套餐钱。
base_url 必须带 /coding。写成 /api/v3 既不抵额度，还会额外出账单——花两份钱办一件事。
超额后付费是手动开关，默认关。额度耗尽时不会自动续，别以为是"用超了没事"。
Agent Plan 仅升不降。想"试一下"的代价是锁死档位，退不回 Coding Plan。

最贵的一次错，可能就发生在一行 curl 上。验证一个 key 通不通，看着无害，但它恰好是"非编程工具直调专属端点"的教科书样本。正确做法：让工具自己发一句话。
