2.1 核心思维的范式转移

2.2 数据流语法规则

2.2.1 颜色匹配原则

2.2.1.1 相同颜色接口代表相同数据类型：紫色对紫色，蓝色对蓝色

2.2.1.2 跨颜色连接的本质报错：数据格式不匹配（Data Mismatch）

2.2.2 节点流向逻辑

2.2.2.1 严格的左进右出单向流向：数据不可逆流

2.2.2.2 如何识别逻辑死循环：系统会变红并停止运行

2.3 核心数据类型解析（避坑指南）

2.3.1 基础数值与文本类型

2.3.1.1 STRING 字符串：纯文本、路径、文件名（注意：不能直接当颜色值用）

2.3.1.2 INT 整数：宽高（必须 8 的倍数）、种子值、步数

2.3.1.3 FLOAT 浮点数：带小数的数值、CFG、Denoise（INT 端口通常不接 FLOAT）

2.3.1.4 BOOLEAN 布尔值：True 或 False、逻辑开关

2.3.2 高级复合对象类型（不可直接互转）

2.3.2.1 IMAGE 图像：像素张量（RGB 数据）

2.3.2.2 LATENT 潜空间：压缩特征（必须通过 VAE Decode 变回 IMAGE）

2.3.2.3 MODEL 加载后的神经元权重大脑

2.3.2.4 CONDITIONING 经过 CLIP 翻译后的语义引导向量

2.4 扩散模型四大支柱的逻辑映射

2.4.1 模型存储：Model/Checkpoint（知识仓库）

2.4.2 语义翻译：CLIP/Text Encoder（翻译官）

2.4.3 采样降噪：KSampler/Sampler（雕刻家）

2.4.4 空间转换：VAE Encode/Decode（压缩机与解压阀）

4 核心硬技能：节点自救与环境手动修复

4.1 当官方管理器失效时的手动挡操作

4.1.1 节点 Component ID 深度搜索法

4.1.1.1 第一步：右键属性面板提取组件 ID（数字指纹）

4.1.1.2 第二步：记事本记录 ID，作为全网搜索的唯一凭证

4.1.1.3 第三步：Google / GitHub 检索归属仓库：解决 Manager 搜不到的痛

4.1.2 逆向比对法与功能替代

4.1.2.1 利用云端平台（RunningHub/Civitai）找原始流程参考

4.1.2.2 寻找同类功能的备选节点：如找不到某个放大节点，找相同算法的替代品

4.2 插件安装与更新的标准 SOP（安全策略）

4.2.1 指令操作基础

4.2.1.1 更新使用 git pull：从云端拉取最新代码

4.2.1.2 安装使用 git clone：克隆仓库到本地

4.2.2 依赖安装三步走（拒绝冲突）

4.2.2.1 第一步：预检（Dry Run）测试：使用 --dry-run 观察是否有依赖冲突

4.2.2.2 第二步：正式安装：使用 --upgrade-strategy only-if-needed（不乱动已有环境）

4.2.2.3 第三步：日志确认：查阅 comfyui-user-comfyui.log 锁定具体报错行

4.3 常见报错解决思路

4.3.1 翻译报错关键词

4.3.1.1 No module named 'xxx'：缺少对应的 Python 依赖库

4.3.1.2 Cuda out of memory：显存炸了，建议降低分辨率或开启低显存模式

4.3.2 类型不兼容解决

4.3.2.1 颜色/文本转换：善用 Color Picker 和 Cast 节点

4.3.2.2 图像/潜空间：检查是否漏连了 VAE Decode
