ComfyUI 工程维护：插件安装、环境稳固与灾难恢复手册

1 维护的核心观念：为什么你必须学会手动管理环境

1.1 管理器（Manager）只是图形化的外壳

1.1.1 它的本质是在后台偷偷运行命令行（CMD）

1.1.2 当网络波动或权限不足时，管理器会显示假成功，导致节点变红

1.2 建立备份双保险体系

1.2.1 物理全备份：应对整个软件、核心文件损坏的极端情况

1.2.2 环境快照：应对由于安装新插件导致的环境冲突（Python 库乱套）

2 第一层保险：物理全备份（手动搬运）

2.1 什么是物理备份

2.1.1 简单粗暴的操作：直接将整个 ComfyUI 根目录复制并粘贴到另一个硬盘

2.2 为什么快照不能代替物理备份

2.2.1 快照只记录了 Python 插件的名字，不包含模型和插件的源代码

2.2.2 如果你的磁盘坏道、或者误删了核心文件，只有物理备份能救命

2.3 建议的操作频率

2.3.1 建议每 15 天或 30 天进行一次全量物理备份

2.3.2 存放建议：最好存放在非系统盘或外部移动硬盘中

3 第二层保险：环境快照（Pip Freeze 备份）

3.1 什么是环境快照

3.1.1 它是一份“DNA清单”，记录了当前所有已安装包的精确版本（如 torch==2.1.2）

3.2 核心操作：如何生成带日期的备份文件名

3.2.1 为什么要带日期：为了在多次尝试中区分哪一个是“昨天的”、哪一个是“刚才的”

3.2.2 Windows 命令行自动获取日期的方法（直接复制使用）

3.2.2.1 提取日期指令：for /f "tokens=2 delims==" %a in ('wmic os get localdatetime /value') do set "dt=%a"

3.2.2.2 截取前八位（年月日）：set "date_str=%dt:~0,8%"

上面是设置日期格式的指令

3.2.3 最终执行的快照指令（环境快照 SOP）

3.2.3.1 完整指令：python.exe -m pip freeze > requirements-backup%date_str%.txt

3.2.3.2 结果说明：执行后会生成一个类似 requirements-backup20260114.txt 的文件

3.3 强制执行频率

3.3.1 每次点击 Manager 里的 Update 或进行任何 git pull 更新操作前，必须跑一遍此指令

4 插件的安全安装与维护：Git 实操

4.1 如何在正确的位置运行指令

4.1.1 动作：进入 ComfyUI/custom_nodes 文件夹

4.1.2 操作：在地址栏输入 cmd 并回车，确保黑色窗口的路径显示在此目录下

4.2 安装插件（Git Clone）

4.2.1 场景：你在 GitHub 发现一个 manager 搜不到的好插件

4.2.2 指令：git clone [仓库地址]（例如：git clone https://github.com/ltdrdata/ComfyUI-Manager.git）

4.3 更新插件（Git Pull）

4.3.1 场景：某个功能不好用了，或者作者说修了 Bug

4.3.2 动作：进入具体插件的文件夹内，再次运行 cmd

4.3.3 指令：git pull（仅下载更新部分，不破坏已有的本地配置）

5 依赖安装的生产级流程（防炸 SOP）

5.1 核心策略：only-if-needed（按需更新，最稳妥的官方推荐策略）

5.2 第一阶段：预检测试（Dry Run）——“先看一眼后果”

5.2.1 指令：python.exe -m pip install -r requirements.txt --upgrade-strategy only-if-needed --dry-run

5.2.2 如何判断预检结果：

5.2.2.1 正常：只显示 Would install（将要安装）缺失的包

5.2.2.2 危险：如果显示 Would uninstall（将要卸载）你正在用的核心包（如 xformers），必须停手

5.3 第二阶段：正式安装

5.3.1 确认无误后，去掉 --dry-run 参数执行正式安装

5.4 故障自查

5.4.1 如果安装报错，查找 comfyui-user-comfyui.log 文件

5.4.2 技巧：将 log 内容发给 AI 助手，并附带提问“请帮我分析哪一行出现了依赖冲突”

6 灾难恢复：环境彻底崩了如何自救回退

6.1 场景识别：更新后 ComfyUI 无法启动，提示版本错误或缺失重要 DLL

6.2 强力恢复指令（Force Reinstall）

6.2.1 逻辑：让 Python 强制卸载现在的错误版本，严格按照你之前快照里的清单重装

6.2.2 指令：python.exe -m pip install -r requirements-backup20260114.txt --force-reinstall

6.2.3 最后的心理准备：回退可能需要较长时间下载文件，请确保魔法网络稳定
