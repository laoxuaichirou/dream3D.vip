ComfyUI 手册 03：报错关键词翻译官

ComfyUI · 整理自 Gary 的教程文档

第三章：报错关键词翻译官

ComfyUI 报错词典与自救逻辑：从“看懂”到“修好”

1 报错排查的“三步走”元逻辑

1.1 第一步：定位报错位置

1.1.1 观察红框节点：标题栏通常显示该节点所属的插件包名

1.1.2 观察黑窗口末尾：最后一两行代码（Traceback）通常是报错的终点

1.2 第二步：识别报错类型

1.2.1 红框报错：代码执行逻辑错误或参数设置非法

1.2.2 紫框报错：资源加载失败（通常是缺模型或路径不对）

1.3 第三步：按图索骥

1.3.1 根据本手册的关键词进行对比，找到对应解决方案

2 第一类：节点与工作流逻辑报错（红框高发区）

2.1 关键词：Arguments missing（缺少参数）

2.1.1 含义：你有一些必填的“插孔”没连线

2.1.2 原因：常见于删除了某些中转节点，导致 K 采样器等核心节点没连上

2.1.3 自救：检查变红节点左侧的所有圆点，确保所有必填项都有连线

2.2 关键词：ZeroSizeError（零尺寸错误）

2.2.1 含义：你试图让 AI 在一张“不存在”的画布上画画

2.2.2 原因：常见于“批量裁剪”节点。如果你图片只有 512，你裁剪位置写了 1024，裁剪结果就是 0

2.2.3 自救：检查裁剪坐标或缩放倍数，确保操作后的像素值大于 0

2.3 关键词：Value not in list（数值不在列表内）

2.3.1 含义：节点下拉框里选的内容，“消失”了

2.3.2 原因：工作流作者用的采样器或模型，你本地没有。比如作者选了 DPM++ 3M，你旧版核心里没这个

2.3.3 自救：手动点击红色的下拉框，重新选一个你本地有的选项

2.4 关键词：False not in [list]（布尔值冲突）

2.4.1 含义：本来该选 1234 的，结果显示了个 False

2.4.2 原因：通常是插件版本更新后，原来的开关逻辑变了，导致旧工作流失效

2.4.3 自救：重新切换一下该节点的开关或下拉菜单，刷新其状态

2.5 关键词：mat1 and mat2 shapes cannot be multiplied（矩阵不匹配）

2.5.1 含义：两份数据“对不上号”

2.5.2 原因：最典型的是 SD1.5 模型接了 SDXL 的组件。它们的底层数据维度天生不合

2.5.3 自救：检查全流程模型版本，确保从 Checkpoint 到 LoRA 到 ControlNet 全是同一系列

3 第二类：硬件与资源限制报错（显存/内存）

3.1 关键词：Allocation on device 0（设备 0 分配失败）

3.1.1 含义：显卡（设备 0）转不动了

3.1.2 原因：显存溢出。你画的图太大，或者开启了太多高耗能插件

3.1.3 自救：重启 ComfyUI；减小生成分辨率；检查是否有其他生图软件占用显存

3.2 关键词：CUDA Out of Memory（显存溢出）

3.2.1 含义：显卡的内存被挤爆了

3.2.2 原因：显存（VRAM）不足以支撑当前计算量

3.2.3 自救：调小 Batch Size（批次）；开启 --lowvram 启动参数；增加系统虚拟内存（辅助手段）

3.3 关键词：CPU and CUDA are not on the same device（设备不统一）

3.3.1 含义：一部分数据在内存，一部分在显存，AI 无法跨界计算

3.3.2 原因：常见于 SAM 探测器等节点。节点里让你选 GPU/CPU，如果你选乱了就会报错

3.3.3 自救：在报错节点里将 device 或 prefer_device 统一设置为 GPU 或 CUDA

4 第三类：环境与依赖缺失报错（黑窗口重灾区）

4.1 关键词：No module named 'xxx'（找不到模块）

4.1.1 含义：你的 Python 环境缺“零件”

4.1.2 原因：新插件安装后，它依赖的第三方库没装。比如 No module named 'cv2' 缺的就是 OpenCV

4.1.3 自救：参考第二部分，执行 pip install [xxx] 或安装该插件对应的 requirements.txt

4.2 关键词：Invalid wheel（无效的包文件）

4.2.1 含义：下载的 Python 包损坏或与当前系统不匹配

4.2.2 原因：网络下载不全，或者你拿 Linux 的包在 Windows 上装

4.2.3 自救：删除当前包缓存，执行强制重装命令 --force-reinstall

4.3 关键词：init 或 ImportError（接口导入失败）

4.3.1 含义：插件的大门打不开了

4.3.2 原因：插件下载残缺，连最基础的启动接口文件（init.py）都没下好

4.3.3 自救：彻底删除该插件文件夹，重新进行 git clone 手动下载

4.4 关键词：module 'comfy' has no attribute 'xxx'（内核属性缺失）

4.4.1 含义：插件在调用一个你的 ComfyUI 根本没有的功能

4.4.2 原因：ComfyUI 核心版本太低，不支持新版插件的高级功能

4.4.3 自救：执行 ComfyUI 核心更新（Update ComfyUI）

5 第四类：模型加载与文件报错（紫色框常见）

5.1 关键词：No such file（找不到文件）

5.1.1 含义：模型名字在，但文件不在那个文件夹里

5.1.2 原因：移动了模型位置，或者文件夹路径带了中文导致 AI 读不出来

5.1.3 自救：检查模型后缀（.pth / .safetensors），确保文件确实躺在指定的 models 目录下

5.2 关键词：NoneType has no attribute 'lower'（空类型错误）

5.2.1 含义：你在试图操作一个“空气”

5.2.2 原因：通常是模型加载失败（None 代表无）。模型损坏、或者是显存不足导致模型被踢出了内存

5.2.3 自救：重新加载模型；检查模型文件大小是否正常（几 KB 的通常是没下完的残次品）

5.3 关键词：mat1 and mat2 mismatch（尺寸不匹配）

5.3.1 含义：模型架构打架

5.3.2 原因：比如你试图用 SD1.5 的 LoRA 去“强修” SDXL 的 Checkpoint

5.3.3 自救：统一全流程架构，1.5 归 1.5，XL 归 XL

6 第五类：网络与连接报错

6.1 关键词：HTTP Error / Connection Error（网络连接错误）

6.1.1 含义：ComfyUI 联网失败

6.1.2 原因：正在下载模型或调用在线 API（如 Gemini/Ollama）时梯子断了

6.1.3 自救：检查魔法上网工具；如果是 Git 报错，需配置 Git 的全局代理

6.2 关键词：SSL: CERTIFICATE_VERIFY_FAILED（证书验证失败）

6.2.1 含义：安全验证没通过，网站不让下

6.2.2 原因：通常是由于魔法工具的证书干扰，或者是 Python 环境证书过期

6.2.3 自救：在命令行执行 pip install --trusted-host 相关参数跳过验证

6.3 关键词：URI 或 URLlib（地址解析报错）

6.3.1 含义：网络地址写错了或者服务器没响应

6.3.2 原因：插件开发者提供的自动下载链接失效，或者你的网络屏蔽了该地址

6.3.3 自救：尝试手动去 GitHub 下载对应的依赖文件
