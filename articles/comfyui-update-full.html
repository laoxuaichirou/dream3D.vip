更新 ComfyUI 主程序 / 自定义插件流程（严谨完整版）

安装/更新插件简化版本丨直接用！

for /f "tokens=2 delims==" %a in ('wmic os get localdatetime /value') do set "dt=%a"

说明

本流程适用于 Git 克隆的 ComfyUI 主程序 和 Git 克隆的自定义插件（ZIP 解压无 .git 目录的项目，见「第五章」单独处理）；

核心原则：先备份、再查看、后更新、补依赖、有兜底，全程规避依赖冲突和环境损坏风险。

命令中的路径，需要替换成你自己的实际路径！

一、 查看更新（确认是否需要更新 + 更新内容）

步骤 1：打开对应目录的 CMD 窗口

打开文件资源管理器，切换到目标目录（你的实际路径！）：

若更新「ComfyUI 主程序」：切换到 G:\Comfyui\COMFYUI_Laoxu\ComfyUI

若更新「单个插件」：切换到 G:\Comfyui\COMFYUI_Laoxu\ComfyUI\custom_nodes\【你的插件目录】

点击文件资源管理器 地址栏，输入 cmd 并回车，快速打开当前目录的 CMD 窗口（避免手动切换目录出错）。

步骤 2：确认远程默认分支（避免分支名错误）

Bashgit branch -r

输出示例：origin/main（远程默认分支是 main）、origin/master（远程默认分支是 master）；

后续所有命令中，需将 origin/main 替换为实际的远程分支名（如 origin/master）。

步骤 3：拉取远程最新信息（不合并代码，仅同步更新记录）

Bashgit fetch origin

作用：确保本地获取到远程仓库的最新状态，避免查询到过时的更新信息；

正常输出：显示拉取的对象数量、分支更新、版本标签等（无报错即成功）。

步骤 4：查看是否有更新 + 简化版更新内容

Bash# 替换 origin/main 为步骤2确认的远程分支名（如 origin/master）git log HEAD..origin/main --oneline

有输出：本地版本落后于远程，输出内容即为「更新记录」（每行 = 简短哈希 + 更新备注，快速了解核心更新）；

无输出：本地与远程版本完全同步，无需更新。

步骤 5：查看详细更新内容（可选，精准了解细节）

Bash# 替换 origin/main 为步骤2确认的远程分支名git log HEAD..origin/main

输出：每个提交的完整信息（作者、提交时间、详细更新说明）；

适用场景：需确认是否修复了自身遇到的 Bug、新增功能是否必要等。

二、 执行更新（安全可控，优先兜底）

前置准备：2 类备份（双重保障，必做！）

备份是更新失败后快速回滚的核心，优先备份目录（一键恢复），再备份依赖快照（环境兜底）

1. 插件 / 主程序目录备份（最优先，一键回滚）

操作方式（手动操作，简单直观）：

关闭 ComfyUI（避免文件占用，导致复制/删除失败）；

在文件资源管理器中，复制目标目录（如插件目录 ComfyUI-SeedVR2_VideoUpscaler）；

粘贴到同一上级目录，重命名为「原目录名_备份_YYYYMMDD」（如 ComfyUI-SeedVR2_VideoUpscaler_备份_20260103）。

作用：更新失败后，直接删除更新后的异常目录，将备份目录重命名回原名称，重启 ComfyUI 即可恢复正常。

2. Python 依赖快照备份（可选，环境回退用）

场景 1：在 批处理文件 (.bat) 中使用（一次性配置，自动生成日期）

里面的路径需要换成你自己的文件路径！

Bash:: 仅在.bat文件中有效，一次性配置日期变量python.exe -m pip freeze > requirements-backup%date_str%.txt

场景 2：直接在 CMD 终端 中使用（依次执行，修改语法避免报错）

每一步的指令，单独复制输入👇

Bash:: 第一步：获取日期变量（终端中需将 %%a 改为 %a）python.exe -m pip freeze > requirements-backup%date_str%.txt

备份频率：建议每月 1 次，或更新重要插件/主程序前必做 1 次；

备份路径：默认在当前 CMD 目录下，推荐切换到便携包 Python 目录备份（统一管理，不易丢失）。

步骤 1：执行更新（Git 命令，明确分支更可控）

确保在目标目录的 CMD 窗口中（插件/ComfyUI 主程序目录）；

执行更新命令（指定分支，避免默认分支混乱）：

Bash# 替换 origin/main 为步骤2确认的远程分支名（如 origin/master）git pull origin main

正常输出：显示 “Already up to date.”（已最新）或 “Fast-forward”（快速更新成功）；

异常情况：若提示「代码冲突」，优先用「目录备份」回滚（新手不建议手动解决冲突，避免源码损坏）。

步骤 2：安装 / 更新依赖（安全无冲突，避免插件加载失败）

核心：使用 --upgrade-strategy only-if-needed，仅安装缺失/必需升级的依赖，不改动现有兼容依赖，最大程度保护环境稳定

切换到便携包 Python 目录（必做，确保依赖安装到便携包内，不污染其他环境）：

Bashcd /d G:\\\\Comfyui\\\\COMFYUI_Laoxu\\\\python_dapao312

依赖安装预检（无报错再执行正式安装，规避风险）：

Bash# 替换 【你的依赖文件路径】 为实际的 requirements.txt 路径（如插件/主程序目录下的 requirements.txt）python.exe -m pip install -r 【你的依赖文件路径】 --upgrade-strategy only-if-needed --dry-run

预检结果判断与处理：

无报错、无核心库（torch/xformers/onnxruntime 等）不必要变动 → 执行正式安装；

有报错 → 优先手动修改 requirements.txt（如指定兼容版本：torch>=2.0.0,<3.0.0），再重新预检；

若冲突无法解决，可尝试删除冲突的依赖项（⚠️ 仅删除非核心库的冲突依赖，勿删除 torch/xformers 等核心库，避免环境损坏），再重新预检。

正式安装依赖：

Bashpython.exe -m pip install -r 【你的依赖文件路径】 --upgrade-strategy only-if-needed

特殊情况：插件无 requirements.txt（针对性安装缺失依赖）

第一步：启动 ComfyUI，查看启动日志（comfyui-user-comfyui.log）；

第二步：日志中会提示 “ModuleNotFoundError: No module named 'XXX'”，记录缺失的依赖名 XXX；

第三步：执行预检（避免版本冲突）：

Bashpython.exe -m pip install XXX --upgrade-strategy only-if-needed --dry-run

第四步：根据预检结果安装：

情况 A：无报错，提示“Would install XXX x.x.x”或“Requirement already satisfied” → 正式安装：

Bashpython.exe -m pip install XXX --upgrade-strategy only-if-needed

情况 B：提示版本冲突/网络错误 → 先解决问题（如指定兼容版本 XXX==x.x.x，或切换 PyPI 镜像源），再重新预检安装：

Bashpython.exe -m pip install XXX==x.x.x --upgrade-strategy only-if-needed --dry-runpython.exe -m pip install XXX==x.x.x --upgrade-strategy only-if-needed

步骤 3：重启 ComfyUI 验证

关闭原有 CMD 窗口和 ComfyUI 进程；

重新启动 ComfyUI；

查看启动日志，无插件加载报错、功能可正常使用 → 更新成功。

三、 问题回退（更新失败快速恢复）

方案 1：优先使用「目录备份」回滚（最简单，一键恢复）

优先级最高，无需改动依赖，直接恢复到更新前的稳定状态

关闭 ComfyUI 及相关进程；

删除更新后异常的插件/主程序目录；

将之前备份的目录（如 XXX_备份_20260103）重命名为原目录名；

重启 ComfyUI → 恢复正常。

方案 2：使用「依赖快照」回退（仅解决依赖问题）

仅当目录备份丢失，且问题明确是依赖导致时使用；优先温和回退，避免强制重装

切换到便携包 Python 目录（根据自己的目录来）：

Bashcd /d G:\\\\Comfyui\\\\COMFYUI_Laoxu\\\\python_dapao312

温和回退（优先推荐，安全高效）：

Bash# 替换 【你的备份文件路径】 为实际的依赖快照路径（如 requirements-backup20260103.txt）python.exe -m pip install -r 【你的备份文件路径】 --upgrade-strategy only-if-needed

核心效果：仅安装/调整快照与当前环境不一致的依赖，不强制重装兼容的核心库，风险极低。

强制回退（仅温和回退无效时使用）：

Bash# 基础强制回退（强制重装所有依赖，覆盖当前环境）python.exe -m pip install -r 【你的备份文件路径】 --force-reinstall --upgrade-strategy only-if-needed

注意：强制回退会卸载并重装所有依赖，可能导致核心库（如 torch）的硬件加速失效，需谨慎使用。

重启 ComfyUI 验证，若仍异常，优先采用「目录备份」回滚（若有）。

四、 补充说明

内置 Manager 适配：可使用 ComfyUI 内置 Manager 替代「第一章 查看更新」的操作（更可视化），但更新仍建议用本流程的 Git 命令 + 手动备份（更可控，避免依赖遗漏）；

批量查看插件更新（Windows CMD）：若需快速排查所有插件更新状态，可在 custom_nodes 目录下执行以下命令（不自动更新，安全无风险）：

Bash# 第一步：切换到 custom_nodes 目录)

输出说明：有内容=该插件有更新，无内容=该插件与远程同步；

核心库保护：预检中若发现 torch/xformers 等核心库将被升级，先暂停操作，前往插件/主程序官方文档确认兼容性后，再决定是否安装；

日志排查：更新后若插件加载失败，优先查看 ComfyUI 启动日志（comfyui-user-comfyui.log），根据报错信息针对性处理（如缺失依赖、版本冲突）。

五、 无.git目录项目的更新方案（ZIP解压下载）

核心原则

无 .git 目录无法增量更新，采用「备份配置 + 下载最新ZIP + 替换源码 + 补依赖」的方式，既保留个性化配置，又获取最新版本。

场景 1：更新无.git目录的ComfyUI主程序

备份关键配置（必做，避免丢失设置）： 关闭 ComfyUI，备份以下文件/目录（复制到非主程序目录，命名为「ComfyUI_配置备份」）：

核心配置：comfyui_settings.json、extra_model_paths.yaml（重中之重，丢失会导致模型路径失效）；

可选备份：models（本地模型，若已迁移到其他盘可忽略）、custom_nodes（插件目录）。

下载最新版本：前往 ComfyUI 官方仓库（https://github.com/comfyanonymous/ComfyUI），点击「Code」→「Download ZIP」，下载最新ZIP压缩包并解压（得到 ComfyUI-latest 目录）。

替换源码：

删除旧 ComfyUI 目录中「除备份文件外」的所有核心源码（如 js、python、web 等目录）；

从 ComfyUI-latest 目录中，复制所有核心源码（js、python、web 等），粘贴到旧 ComfyUI 目录（覆盖原有文件）；

将备份的配置文件（comfyui_settings.json 等）粘贴回旧 ComfyUI 目录，覆盖默认配置。

补装依赖：参考本流程「第二章 步骤2」的依赖安装方式，安装最新依赖（执行主程序目录下的 requirements.txt）。

重启验证：确认 ComfyUI 正常启动，个性化配置生效。

场景 2：更新无.git目录的自定义插件

备份配置（可选）：若插件目录下有个性化配置文件（如 xxx_config.json），先复制备份到临时目录。

下载最新版本：前往插件官方仓库，下载最新版本的 ZIP 压缩包并解压（得到 XXX-Plugin-latest 目录）。

替换插件（两种方式可选）：

方式 A（新手推荐）：删除旧插件目录，将 XXX-Plugin-latest 目录重命名为「旧插件目录名」（保持与原来一致，避免 ComfyUI 无法识别），粘贴备份配置（如有）。

方式 B（进阶）：保留旧插件目录中的配置文件，删除核心源码（.py、.js 等），从 XXX-Plugin-latest 目录复制核心源码，粘贴到旧插件目录（覆盖原有文件）。

补装依赖：参考本流程「第二章 步骤2」的依赖安装方式（有无 requirements.txt 均适用）。

重启验证：确认插件正常加载，功能生效。

补充说明

更新前必须关闭 ComfyUI，避免文件占用导致替换失败；

无 .git 目录无版本跟踪能力，备份是唯一兜底方案，切勿省略；

无法通过命令查看更新内容，需前往插件/ComfyUI 官方仓库的「Releases」或「Changelog」文档查看。

六、 常见问题排查

Git 命令报错「unknown revision or path」：确认远程分支名正确（通过 git branch -r 验证），将命令中的 origin/main 替换为实际远程分支（如 origin/master）；

依赖安装报错「WinError 5 拒绝访问」：确认便携包目录已配置「完全控制」权限（右键目录 → 属性 → 安全 → 编辑 → 勾选当前用户的「完全控制」）；

插件加载失败「ModuleNotFoundError」：按日志提示针对性安装缺失依赖（参考「第二章 步骤2-5」）；

核心库升级后功能异常（如 torch 升级后 CUDA 失效）：使用依赖快照回退到之前的稳定版本（参考「第三章 方案2」）。
