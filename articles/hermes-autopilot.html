📖 先搞懂一件事

大多数人的用法是：打开聊天 → 提问 → 等回答 → 关闭。但 Hermes 真正的威力在于定时任务（cron）——你可以让它每天固定时间自动干一件事，做完把结果发给你。

关键在于：很多任务根本不需要 AI 动脑。比如"检查磁盘是不是快满了"，一段 5 行的小脚本就能判断，完全不用调用模型——也就意味着零成本。只有真的需要动脑的环节，才值得花模型费。

💡 全文最贵的坑，记住这一条就够了：脚本输出里千万别带时间戳。哪怕内容没变，时间戳一变，系统就以为"页面变了"，每次都白白调用模型。

🕐 小白必修课： cron 时间表怎么看

定时任务的第一段是 5 个数字，代表"什么时候执行"：

分钟0–59
小时0–23
几号1–31
几月1–12
周几0–6
"0 8 * * *" = 每天 8:00
"0 9 * * 1" = 每周一 9:00
"0 */6 * * *" = 每 6 小时一次

💡 新版 Hermes 还支持更人性化的写法："30m"（每30分钟）、"every 2h"（每2小时）。

10 个自动巡航配置

每个都附带：干什么 · 为什么 · 怎么工作 · 一条命令 · 一个坑

01

网页监控 · 变了才叫醒 AI

有变化才花模型费

干什么定时检查一个网页，只有内容真的变了才通知你：价格、更新日志、招聘信息、签证放号……

为什么普通监控每次都要问一遍模型"有没有变化？"——为了 1 次有用的提醒，你先付了 28 次"没变化"的钱。

怎么工作每次先抓取网页原文，跟上次做逐字节比对。完全一样 → 直接结束，不调用模型；不一样了 → 才把差异交给模型分析。

hermes cron create "0 */6 * * *" "告诉我变了什么" \
  --name watch-price \
  --monitor-url https://example.com/pricing \
  --deliver telegram

试试商品价格页 · GitHub releases 页 · 签证/预约放号页 · 竞对定价页

⚠️ 坑：有些页面每次打开都会变（时钟、"最后更新于"时间、轮播广告），系统会认为"每次都变了"。这种页面要用 --monitor-script 写个小脚本，只提取你关心的那一小块内容，输出里绝不能含时间戳。
02

手机晨报 · 每天一条消息看全天

轻量模型即可

干什么每天早上，Hermes 看一遍你的日程、邮件和天气，浓缩成一条短消息发到你的聊天软件。

为什么替代"起床后连开四个 App 花掉的 15 分钟"。

怎么工作到点后自动开始一次新任务，挂载 google-workspace 技能就能读你的日历和 Gmail，结果像普通消息一样发到 Telegram。

hermes cron create "0 8 * * *" \
  "用3条要点、80字以内总结：今天的日程、需要回复的邮件、天气" \
  --name morning-brief \
  --skill google-workspace \
  --deliver telegram

试试早晨简报 · 晚间"明天有什么" · 周五"这周我错过了什么"

⚠️ 坑：提示词一定要写具体（"3条要点、80字以内"）。提示词模糊，早上 8 点你会收到一篇小作文。
03

健康检查 · 零模型费，出事才说话

完全不花模型费

干什么定时运行你自己的检查脚本，只有出问题时才发消息。

为什么"磁盘满了吗？""Key 过期了吗？""网站还活着吗？"——这些判断不需要 AI，每天为此调用模型纯属浪费。

怎么工作加上 --no-agent 后，脚本本身就是全部任务：脚本的输出原样发给你。输出为空 = 不发消息。所以脚本平时保持沉默，出问题才打印一行。

hermes cron create "0 9 * * *" \
  --name health-check \
  --script check_keys.py \
  --no-agent \
  --deliver telegram

试试API Key 到期提醒 · 磁盘空间 · 网站是否正常返回 200 · 夜间任务是否产出了文件

⚠️ 坑：脚本成功时一个字都别打印。多打一行 "OK"，你就每天收到一条废话消息。脚本放在 ~/.hermes/scripts/ 目录下，.sh 用 bash 跑，其他按 Python 跑。
04

夜间备份 · 纯调度，无模型

完全不花模型费

干什么每天深夜自动运行你的备份脚本。

为什么备份这种事，永远是"需要它的那天"才想起从来没做过。它不需要 AI，只需要可靠的闹钟。

怎么工作和 03 号一样的无模型模式：Hermes 只当闹钟。不加 --deliver 的话结果只存在本地，随时用 hermes cron list 查看每次运行记录。

hermes cron create "0 3 * * *" \
  --name nightly-backup \
  --script backup.py \
  --no-agent

试试日备 + 周备 + 月备，建三个任务、三个时间表即可

⚠️ 坑：先手动跑一遍脚本确认它能正常工作。一个"默默复制了个空文件夹"的备份任务，比没有备份更害人——它给了你虚假的安全感。
05

周一催办 · 谁还在等你回复

只起草，不代发

干什么每周一，Hermes 读你最近的邮件往来，列出"你该回的"和"你在等对方回的"，并把回复草稿写好。

为什么别人周二问的问题，到周五早被三封新邮件埋得找不到了。这个任务就是把它挖出来。

怎么工作内置的 email-inbox-triage 技能会读完整对话（不只是最新一封），区分"我欠谁的"和"谁在欠我"，每条结论都附上原文引用方便你核对。草稿留在聊天里，它永远不会替你发送。

hermes cron create "0 9 * * 1" \
  "列出我欠的回复和我在等的回复，并起草回复。只起草，不发送。" \
  --name monday-inbox \
  --skill email-inbox-triage \
  --deliver telegram

试试客户跟进 · 团队里没人答的问题 · 还没付的账单

⚠️ 坑：需要先配好邮箱（Himalaya 或 Google Workspace）；你的邮件内容会发给模型服务商。每封草稿发送前必须自己读一遍。
06

任务记性好 · 本次看得到上次

防重复汇报

干什么让定时任务记住自己上一次的输出。

为什么没有记忆的话，每次运行都从零开始：今天报一遍"新发现的链接"，明天同一批又当新的报一遍。

怎么工作加上 --continuity 后，每次运行时，上一次的输出会自动加进这次的提示里。任务就能跳过已经汇报过的内容，接着上次的往下做。第一次运行不受任何影响。

hermes cron create "0 18 * * *" \
  "汇总今天的新进展，跳过上次已汇报的内容" \
  --name daily-digest \
  --continuity \
  --deliver telegram

试试持续更新的项目日志 · "自上次以来"的增量摘要 · 不再重复推同一个链接的情报收集

⚠️ 坑：它只记住这个任务自己的上一次输出，不是你的全部历史。要记长期事实，用 Hermes 记忆，或让任务自己写到一个文件里。
07

例行任务绑便宜模型

高频任务省钱关键

干什么给某个定时任务单独指定一个更便宜的模型。

为什么默认情况下，定时任务用"运行那一刻你的主模型"。如果主模型是贵的旗舰款，那每篇例行摘要都在按旗舰价计费。

怎么工作--model 把这一个任务锁定到指定模型（必要时配 --provider 指定服务商）；你日常聊天仍用主模型。--pin 是另一种锁法：把"当前主模型"钉死在这个任务上——以后你换主模型，也影响不到它。

hermes cron create "0 * * * *" \
  "总结过去一小时的监控记录" \
  --name hourly-summary \
  --model glm-4.5-air --provider zhipu

试试每小时摘要 · 日报周报 · 监控类任务——所有"跑得多但不难"的活

⚠️ 坑：太小的模型在难任务上会漏事。便宜模型留给例行走量任务，真正烧脑的活还是用旗舰。另外这个参数只能你自己在命令行设，Agent 会话里的 cronjob 工具改不了它。
08

主模型挂了 · 自动切换备用

无人值守的保险

干什么给 Hermes 配一串备用服务商/模型，主模型失败时按顺序自动切换。

为什么凌晨 3 点跑的任务，没有任何人会帮它重试。一次限流或故障，这个任务就悄悄蒸发了。

怎么工作主模型遇到限流、过载或连接错误时，自动尝试降级链里的下一个。hermes fallback add 会打开和 hermes model 一样的选择器，挑一个服务商+模型即可。

hermes fallback add     # 挑一个备用服务商+模型，追加到链尾
hermes fallback list    # 查看整条降级链
hermes fallback remove  # 删掉某个备用

试试所有"你睡觉/出门时运行"的任务

⚠️ 坑：备用模型是另一个服务商，回答风格会有点不一样。链上第二位放一个你信任的模型，而不是单纯最便宜的。
09

多 Key 池 · 限流了自动换一把钥匙

按 Key 计费才需要

干什么同一个服务商下可以添加多把 API Key，组成钥匙池。

为什么一把 Key 撞上限流或额度上限，任务就停了——哪怕你的服务商本身一切正常。

怎么工作同服务商的 Key 组成一个池：一把不健康了自动轮转到下一把。池子先试；池里全部用尽了，才轮到 08 号的跨服务商降级链接手。

hermes auth add         # 给当前服务商再加一把 Key（可重复添加）
hermes auth list        # 查看每个池里有哪些 Key

试试OpenRouter、Anthropic 这类按 Key 计费的服务商。如果你用的是 Nous Portal，一次登录覆盖 300+ 模型，大部分人不需要建池。

⚠️ 坑：提示词缓存是跟着 Key 走的。池中切换 Key 后，下一次请求要把整个对话历史按全价重新读一遍。轮转保证你不中断，但不保证免费。
10

别再反复点"同意"了

一次配置，长期省事

干什么扫描你的历史记录，找出那些你批准过一次又一次的命令，提议以后别再问你了。

为什么自动化的天敌是：每次运行都卡在等你对一个"已经批准过 20 次"的命令点"同意"。

怎么工作扫描会话历史（默认最近 90 天），把"至少批准过 2 次"的高频命令排成编号列表。在你用 --apply 挑选之前，什么都不会改。破坏类命令（递归删除、sudo、写磁盘、改凭证）永远不会被提议。

hermes approvals suggest              # 先只看列表
hermes approvals suggest --apply 1,3  # 确认后合并进白名单
hermes approvals suggest --days 30    # 只看最近30天

试试每天自动任务里反复出现的 build / test / git 命令

⚠️ 坑：只放行那些闭着眼也会同意的命令。其他继续让它问——问你，是它的职责，不是缺点。
