HERMES AGENT 实用指南

先配置什么，
后配置什么？

先把模型、安全和记忆理顺，再逐步添加备用方案和工具。不要一开始就陷进插件和配置的海洋。

这不是一份必装清单根据一条社区经验整理，分级是作者观点；功能入口随版本变化，请结合你使用的版本核对。
优先处理尽早完善按需调整有需要再接三个避坑点
S

先把基础配好

影响每次使用的能力、安全与连续性。

模型与服务商

模型决定回答能力，也影响速度和成本。先选符合任务和预算的模型，再考虑扩展。

hermes model

安全与授权

对危险命令保留确认。先看清操作对象，再授权；不要把“自动执行”当成默认安全。

长期记忆

让它记住稳定偏好和长期背景。任务细节放在项目资料里，别把记忆塞成流水账。

安全边界：授权机制主要针对危险命令等风险操作，并不意味着所有操作都会逐条弹窗。具体规则和界面会随版本变化。
A

让工作流更稳

开始长期使用后优先补齐。

可复用的 Skills

把反复使用的做事方法交给技能；先解决实际任务，不必为了数量安装一大堆。

hermes skills

备用模型

主模型或服务商出错时，备用链可以尝试接手；要提前检查认证和可用性。

hermes fallback

备份与恢复

更新、迁移前先备份重要资料，还要确认备份包含什么，以及恢复方式是否可行。

hermes backup --help

定时任务

把重复检查、整理和通知交给定时任务，并检查任务到底有没有按预期执行。

hermes cron list
容易漏掉：官方文档说明，固定指定模型、服务商或接口地址的定时任务，不继承全局备用模型链。备份可能包含凭据，分享前不要直接外传。
B

按任务调整

不是越高、越多就越好。

推理强度

简单任务先用较轻档位，复杂分析再提高。实际耗时和费用要看模型与任务。

长对话压缩

对话很长时，压缩可以控制上下文体积，但重要事实仍应写进可查找的项目记录。

可用工具

按场景开放必要工具，减少无关工具和误操作面；工具并非越多越好。

hermes tools
C

有需求再接

优先解决问题，而不是堆功能。

插件

需要某种特定扩展能力时，再核查来源、许可和兼容性。

hermes plugins

MCP 连接

需要操作外部服务或专用工具时接入，同时留意权限和上下文开销。

hermes mcp

独立 Profile

需要区分工作、配置或独立实例时使用；隔离并不会自动验证所有实例。

hermes profile
皮肤和桌宠属于个人化功能，可以最后再调。对某些需要多实例或外部工具的用户，Profile 和 MCP 也可以提前，优先级应服从实际工作。
F

三个常见坑

原帖建议避免的做法。

跳过危险操作确认

尤其是面向真实项目和文件时，不要轻易使用跳过危险命令授权的模式。

所有任务都开最高思考

小任务也用最高档，可能增加等待和费用。先根据难度选合适档位。

没有备份就更新

更新前先确认备份与恢复路径。备份可能含密钥，不能直接外传。

记住这个顺序就够了

模型→安全→记忆→备用与备份→按需扩展

这是一份上手思路，不是对所有工作流都适用的硬性排名。版本和不同使用界面的入口可能不同。
