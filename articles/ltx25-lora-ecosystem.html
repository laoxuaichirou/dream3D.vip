LoRA 生态不是 35 个滤镜

从视频修复、VFX、角色一致性到空间音频，LTX‑2.5 的 LoRA 已经形成一套“小型后期系统”。这篇教程帮你分清哪些是官方主力、哪些需要专用工作流，以及第一轮到底该测什么。

35 个页面条目，不等于 35 种独立能力。里面包含重复权重、私人身份模型、蒸馏兼容实验，以及不能直接放进普通 LoRA Loader 的研究模型。

02 / Bottom Line

四个结论先拿走

如果只想快速理解这一轮调研，记住下面四句话就够了。

DETAIL

修复不等于忠实还原

Refine Details 和 Pixel Upscaler 都会生成新细节，必须检查假纹理、身份漂移和闪烁。

WORKFLOW

专用控制不能只挂 LoRA

Slow Motion、SepGen、BBox 等需要专用节点或接线，普通加载方式不代表模型无效。

BASE MODEL

蒸馏 LoRA 不能乱叠

本机已有 distilled INT8 基座，不能再默认叠加面向 dev 基座的蒸馏 LoRA。

TEST

先做最小单变量 A/B

一项能力、一个素材、同 prompt/seed/帧数，过 Gate 后再扩 seed 和素材矩阵。

03 / Official Models

官方 14 项：主力能力全景

使用下方筛选快速定位任务。卡片同时写清适用场景与不能混淆的边界。

Alpha‑Gen

本机已跑通

RGB 视频 → 逐帧灰度 Alpha Matte

人物、动物、玻璃、烟火与发丝等软边抠像。

不能指定抠哪个物体；钢琴素材出现错误保留，用户完整回放仍待完成。

官方模型卡 ↗

Layout‑To‑Render

来源宣称

3D 灰模 / Playblast → 完成镜头

把 Blender、Unreal 的运动与机位转换成有美术风格的成片。

需要合格 layout 与首帧；没有 3D 预演素材时不值得优先测试。

Refine‑Details

P1

重建纹理、边缘与颗粒细节

LTX 成片二次精修、中远景脸、Logo、衣服和背景细线。

不是忠实超分；4K 很吃显存，16GB 显卡应从短片低分辨率 Gate 起步。

官方模型卡 ↗

Ingredients

P1

参考表 → 角色 / 道具 / Logo 一致性

系列角色、品牌广告、多道具场景与跨镜角度一致性。

输入 reference sheet 的规范程度，会直接决定是否发生职责串扰。

官方模型卡 ↗

SDR‑To‑HDR

专用链

8-bit SDR → 16-bit HDR

ACEScg EXR、HLG 成片与规范 HDR 母版流程。

需要 HDR 显示与色彩管理链；没有交付需求时不值得先测，且不生成音频。

Pixel Spatial Upscaler

P2

干净低清视频 → 2× 生成式放大

约 280p 草稿和干净低清参考，生成高频细节。

Creative Upscaler 不是像素忠实还原，也不负责压缩伪影。

Cinemagraph

来源宣称

静帧 → 局部运动无缝循环

水、霓虹、反射、雨、蒸汽等单一运动元素。

静态机位最稳，不适合人物全身运动或复杂镜头移动。

Day‑To‑Night

P2

日景视频 → 夜景重打光

街景、外景、风景，尽量保留原构图、镜头与主体运动。

约 4 秒 / 97 帧接近训练分布；长片尾部可能漂移。

Clean‑Plate

P2

移除人物 / 车辆并重建空背景

VFX 清底、去路人、去车辆和场景素材准备。

大面积遮挡或背景信息不足时会臆造。

Deblur

来源宣称

修复失焦与虚焦

对焦失败、镜头柔焦，目标是重新恢复可读细节。

不处理运动模糊、压缩伪影或超分；极端虚焦必然生成猜测细节。

Decompression

来源宣称

去宏块、振铃、色带与色度渗漏

低码率传输视频、老网片和重压缩素材。

不负责虚焦、运动模糊、噪点、上色或空间放大。

Colorization

来源宣称

黑白 / 单色视频 → 自然上色

黑白档案、去色素材和视觉复原。

颜色是模型的合理生成，不等于真实历史色；高于训练桶时可能减弱。

Slow‑Motion Control

P1

用 speed 数值控制真实慢动作

水花、头发、布料、打斗、旋转和液体等可观察运动。

必须使用双 fps / speed 专用接线；普通 LoRA Loader 不会得到预期控制。

官方模型卡 ↗

Water‑Simulation

P2

为原视频生成水体与湿反光

河流、雨、水瀑、洪水、飞溅与环境改造。

是生成式水体而非物理仿真；必须重点检查接触、遮挡和时序连续。

04 / Community

社区 21 项：真正值得看的方向

社区模型更像实验场。重点不在下载量，而在它是否解决官方生态还没覆盖的任务。

LTX‑Ripple

P1

只修改视频第一帧，再把衣服、Logo、背景、天气或风格变化传播到整段视频。最适合验证“修一帧，能不能修完整片”。

模型卡 ↗

BBox‑Control

研究型

通过包围盒与区域提示控制主体位置、内容和运动。价值高，但需要专用 ComfyUI 节点。

ainvfx‑fluid

VFX

在首尾帧画色块，让模型生成烟、蒸汽或火焰。属于可控视觉预演，不是流体物理求解。

Exploded‑View

产品

由产品图生成零件爆炸分解动画，适合电脑、汽车、手表、建筑和鞋类展示。

Golden‑Hour

重打光

普通日光转黄金时刻。与官方 Day‑To‑Night 同类，第一轮不必同时占用测试矩阵。

AKUSPACE

音频

给音频添加房间、户外空间、混响和声学特征，并保持画面同步；需要自定义节点和 acoustic caption。

05 / Audio Research

SepGen 两个模型到底差在哪？

它们属于同一个研究项目、同一个 327M 参数音频流 LoRA，但任务方向相反。

Separation · sep‑12k

拆声音
已有视频+混合音频+声源描述→多个 Stems
  • 任务：Audio‑to‑Audio 分离。
  • 输出：人声、乐器、环境音等独立音轨。
  • 只做分离时，优先选择这个 checkpoint。
ModelScope 镜像 ↗

Generation · gen‑3k

生声音
场景描述+声源描述→视频+混音+Stems
  • 任务：Text‑to‑Video 音画联合生成。
  • 在 sep‑12k 上继续训练 3,000 步。
  • 需要生成功能必须选它，同时也能执行分离。
ModelScope 镜像 ↗
不能当普通 LoRA 直接加载。 SepGen 依赖 block-diagonal caption routing、受保护的 audio-mix span、Cross‑Stem Attention Guidance 等专用机制，必须使用项目代码；仅在 ComfyUI 中挂权重无法复现论文流程。
06 / Test Plan

第一轮只测四个互补 Gate

四项分别回答四个不同问题。Alpha‑Gen 已有三 seed 历史测试，不重复占用名额。

Refine‑Details｜细节到底有没有变好？

取现有 LTX 数字人口播 49 帧短段，原片与 LoRA 同分辨率对照；从 512/704 档开始，不直接挑战 4K。

眼口衣服纹理背景细线假细节时序闪烁

LTX‑Ripple｜改一帧能否贯穿全片？

同一段 4 秒视频，只在第一帧改变衣服颜色、Logo 或背景牌面；无 LoRA 与 Ripple@1.0 保持同 prompt/seed。

变化持续遮挡恢复身份漂移误改区域

Ingredients｜参考表能否守住一致性？

用授权或合成人物制作 reference sheet，包含正侧面、两件道具、场景与 Logo；对照仅 prompt 与 prompt+参考表。

身份服装Logo 拼写道具数量跨镜角度

Slow‑Motion｜速度旋钮是否真的有效？

同一首帧与提示词，仅改变 speed=1.0 / 0.2；选水花、布料或头发等具有明确物理运动的素材。

真实变慢非重复帧非糊帧音画同步身份一致
07 / Decision

哪些先测，哪些先放下

测试顺序不是能力排行榜，而是结合现有素材、本机环境和项目价值后的选择。

现在测高价值、易做单变量

  • Refine‑Details：直接对应中远景脸和纹理问题。
  • LTX‑Ripple：适合验证视频修补能否跨帧传播。
  • Ingredients：验证人物、道具、Logo 一致性。
  • Slow‑Motion：数值控制，容易做清晰 A/B。

暂缓缺少条件或价值重叠

  • SepGen：需要专用代码，不属于普通 LoRA Gate。
  • SDR‑To‑HDR：需要完整 HDR 显示和色彩管理链。
  • 私人身份 / 重复镜像：项目价值低或能力重复。
  • 蒸馏 LoRA：与本机 distilled INT8 基座存在叠加风险。
